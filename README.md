# 귀신의 집 대기 접수

GitHub Pages 화면 + Cloudflare Workers / D1 서버 구성입니다.
접수용 태블릿과 운영진 휴대폰의 명단을 5초마다 동기화합니다.

## 구현된 기능
- 팀 대표 학번, 이름, 전화번호, 전체 인원 접수
- 서버에서 중복 없는 대기번호 자동 발급
- 통신 실패 후 재시도 중복 발급 방지, 대기/호출/부재 팀의 동일 전화번호 중복 접수 방지
- 운영진 명단 조회, 검색, 상태 필터, 전화번호 마스킹/보기
- 호출, 입장 완료, 부재, 취소, 신규 접수 마감 및 재개
- 공개 호출 현황(개인정보 없음), 비밀 링크로 개인 번호표 조회(이름/전화번호 없음)
- 전체 명단 삭제(번호 카운터는 유지하여 기존 번호와 혼동 방지)
- 가상 정보로 연습하는 체험 모드(현재 탭 메모리만 사용)

**현재 문자/카카오톡/푸시 알림은 발송하지 않습니다.** 호출은 사이트 화면에 반영됩니다.
번호표 링크를 복사하거나 대기번호를 촬영/메모해서 보관하세요. QR 생성은 이 버전에 포함하지 않았습니다.
체험 모드는 실제 접수용이 아닙니다. 다른 기기와 동기화되지 않으며 새로고침 시 모두 사라집니다.

## 1. GitHub에 업로드
1. 새 저장소를 만듭니다. 예: `ghost-queue`.
2. 압축을 풀고 `docs`, `server`, `tests`, `README.md`, `package.json` 등을 저장소 최상위에 업로드합니다.
3. Settings → Pages → Build and deployment → Deploy from a branch.
4. Branch는 `main`, 폴더는 `/docs`로 선택하고 Save.
5. 발급된 사이트 주소로 접속합니다. 아직 서버를 설정하지 않았다면 체험 화면이 나오는 것이 정상입니다.

GitHub Pages는 HTML/JS를 제공하는 정적 호스팅입니다. 실제 명단 저장 및 여러 기기 동기화에는 아래 서버가 필수입니다.

## 2. Cloudflare 서버 만들기 (컴퓨터에서 1회)
Cloudflare 계정과 Node.js/npm이 필요합니다. 해당 계정의 Workers/D1 사용 가능 여부 및 할당량을 확인하세요.
다운로드한 프로젝트의 `server` 폴더에서 터미널을 엽니다.

```bash
npx wrangler login
npx wrangler d1 create ghost-queue
```

출력에서 `database_id` 값을 복사해 `server/wrangler.toml`의 `REPLACE_WITH_D1_DATABASE_ID`를 바꿉니다.
`ALLOWED_ORIGIN`에는 GitHub Pages 주소의 **출처만** 넣습니다.
예: 사이트가 `https://myname.github.io/ghost-queue/`라면 `https://myname.github.io`.
끝의 `/`와 저장소 경로를 넣지 않습니다.

```bash
npx wrangler d1 execute ghost-queue --remote --file=schema.sql
npx wrangler secret put ADMIN_KEY
npx wrangler secret put KIOSK_KEY
npx wrangler deploy
```

- ADMIN_KEY: 운영진 전용 비밀번호. 무작위로 만든 20자 이상의 값을 권장합니다.
- KIOSK_KEY: 접수 기기용 비밀번호. ADMIN_KEY와 다른 무작위 20자 이상 값을 사용하세요.
- `secret put` 실행 후 입력창에만 입력합니다. 파일, GitHub, 대화창에 비밀번호를 적지 마세요.
- 접수 키로는 전체 명단을 조회할 수 없습니다. 잠금 해제된 태블릿은 접수 담당자가 관리하세요.
- 배포 결과의 `https://....workers.dev` 주소를 복사합니다.

## 3. 화면과 서버 연결
`docs/config.js`의 `apiBase`에 Worker 주소를 넣고 GitHub에 반영합니다.

```js
apiBase: "https://본인-워커.본인-계정.workers.dev"
```

`eventName`에서 행사 이름, `maxPeople`에서 팀 최대 인원(1~10)을 바꿀 수 있습니다.
기본 화면 최대 인원은 6명입니다. 서버 검증 범위는 1~10명으로 설정되어 있으므로, 엄격한 인원 상한이 필요하면 worker.mjs의 validate 함수 상한도 함께 변경하세요.
`retentionNotice`의 기본 문구는 “행사 종료 후 24시간 이내 삭제”입니다. **자동 삭제 기능은 아니므로 실제 삭제를 실행해야 합니다.**

## 4. 행사 당일 운영
1. 태블릿으로 사이트 열기 → 접수용 KIOSK_KEY 입력 → 학생에게 접수 화면 제공.
2. 운영진 휴대폰으로 같은 사이트 → 운영진 → ADMIN_KEY 입력.
3. 대표 학번/이름/전화번호/인원 입력 후 번호 발급. 번호를 촬영/메모하도록 안내.
4. 운영진의 “다음 대기 팀 호출”로 호출하고, 입구로 온 팀의 번호 확인 후 “입장 완료”.
5. 호출한 팀이 없으면 “부재”. 부재 팀은 일반 대기 순서에서 제외됩니다. 돌아온 팀은 운영진이 개별적으로 “호출”합니다.
6. 호출 현황 화면은 다른 기기/모니터에 띄울 수 있습니다. 개인정보 없이 호출 번호만 표시합니다.
7. 접수 종료 시 “접수 마감하기”. 기존 대기 팀은 계속 관리할 수 있습니다.
8. 행사 종료 후 약속한 보관 기간 내 “전체 명단 삭제” 실행. 되돌릴 수 없습니다. 이후 필요 없다면 Cloudflare D1 데이터베이스와 Worker도 정리하세요. 공급자 백업/복구 보존 정책은 별도로 적용될 수 있습니다.

### 꼭 미리 연습할 항목
- 실제 태블릿 + 운영진 휴대폰 두 기기에서 명단 동기화 확인
- 동일 전화번호 중복 접수 차단, 인원/학번/전화번호 오류 입력 확인
- 호출 → 부재 → 재호출 → 입장 완료, 접수 마감/재개 확인
- 학교 Wi-Fi로 Worker 접속 가능한지 확인
- 휴대폰이 없는 팀을 위한 종이 번호 메모 준비
- 통신 실패 때는 마지막 번호를 확인하고 종이 접수로 전환. 체험 모드로 전환해서 실접수하지 말 것

## 개인정보와 보안
- 실제 접수 데이터는 GitHub에 저장하지 않습니다. Cloudflare D1에 저장됩니다.
- 운영진 화면 주소는 공개되어도 API는 관리자 키가 없으면 명단을 반환하지 않습니다.
- 관리자/접수 키는 브라우저의 현재 탭 메모리에만 저장됩니다. 새로고침하면 다시 로그인합니다.
- 학생 번호표는 무작위 비밀 토큰으로 조회합니다. 링크를 공유하지 않도록 안내하세요.
- 개인정보 수집 안내는 담당 선생님과 실제 운영 목적/보관 기간에 맞춰 확인하세요. 동의하지 않은 학생의 현장 접수 방법도 마련하세요.
- 키는 강한 무작위 값으로 설정합니다. 대규모 장기 서비스용 계정 관리/로그인 시도 제한은 포함하지 않은 행사 기본 버전입니다.
- 서버 요청 데이터는 별도 콘솔 로그로 출력하지 않습니다.

## 메시지 발송 연결 시
현재 UI에서 발송했다고 표시하지 않습니다. 실제 문자/알림톡 연결 시 서버에만 발송 API 키를 보관하고, 접수/호출마다 고유 발송 식별자와 발송 결과 저장을 추가해야 합니다. 재시도 중복 발송 방지, 실패 표시 및 수동 재전송도 함께 구현해야 합니다.

## 테스트 및 검증 범위
Node.js 22.13 이상에서 프로젝트 루트:

```bash
npm test
```

SQLite 기반 로컬 어댑터로 서버의 접수/중복방지/조회 권한/공개정보 제한/상태 전이/삭제를 검증했습니다. JS 문법 검사도 통과했습니다.
실제 Cloudflare 배포, 브라우저 시각 QA, 학교 네트워크 및 문자/알림톡 발송은 검증하지 않았습니다.
